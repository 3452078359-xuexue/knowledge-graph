# 贵阳市景区数据

**口径：高德出骨架，百科出内容。**
基础数据（id、坐标、地址、行政区、类型）一律取自高德 POI；
百度百科只进知识层丰富实体，不得覆盖坐标、地址、评分、营业状态等事实字段；
社媒（小红书）只作体验证据，不新建也不覆盖 POI。

**② 类型污染逐条判定，不一刀切**

判定规则：**单体商户撤，集合型街区留**。
schema 说「`Area` 不用于表示餐饮、住宿、商店」指的是单体商户 ——
而 `areaType` 枚举里明确有「市集 / 步行街 / 农贸市场」，说明集合型是合法的。

| 处置 | 条数 | 例 |
|---|---:|---|
| 撤（单体商户/住宅/洗浴） | 7 | 小卖部 ×2、单体餐厅 ×2、住宅小区 ×2、洗浴 ×1 |
| 改 `areaType` | 5 | 双子塔→地标、青云路步行街→步行街、青云市集/止庐市集/百卉园→市集 |
| 标待核（**无证据不删**） | 2 | 观园（地址在观山湖公园内，厂商归住宅小区疑似有误）、十二生肖 |

**③ 坐标重合：逐组核对厂商实时数据后记判定**

5 组重合中 2 组为真重复（息烽集中营两条、川主庙与四川会馆），
按 schema `possibleSameAs`「仅保存待人工判断的候选、不做字段融合」记候选并置 `ambiguous`，**不自动合并**。
另 3 组经核对为**厂商本身即给出同一坐标**（非本项目精度丢失），
判定为真实不同对象、坐标继承自同一父对象，已逐条记 `_coordNote`。

> 严格讲这类 `geoPrecision` 应为 `approx`（继承点），但 `approx` 会使其退出附近排序 ——
> 而藏经楼、玉佛殿确实位于该点位、游客问「附近有什么」应当看到。
> 此处保留 `exact` 并记录说明，是否改判留作产品决定。

## 验证

```bash
python3 ../../04_验证报告/景区数据语义审核.py
```

既有 `贵阳市景区结构化表格验证报告.json` 的 24 项中 **18 项是行数/列数/字段顺序**，
只有 6 项涉及语义，且**没有一项检查实体该不该存在** ——「综述」「生聚教训」当年就是这样全过 24 项的。
本语义审核 19 项专查那些查不到的：实体存在性、枚举越界、类型纯度、
H3 与坐标重算比对、跨实体层级、重复、关系语义、内容完整度。

审核区分「**未处理**」与「**已决策并记了理由**」—— 已逐条决策的不再标红，
判定依据是有没有留下可追溯的记录，不是指标本身。
