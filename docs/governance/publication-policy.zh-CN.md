# 公开数据与治理策略

## 目的

本仓库向所有人公开知识图谱设计、Schema、H3 空间框架以及贵阳和泰国两个正式交付包的脱敏数据快照。它是可查询、可下载、可复核的数据发布层，不是本地采集运行目录的逐字节复制。

## 公开范围

- 自研 Schema、字段说明、查询与证据治理设计；
- 官方或开放来源的行政区、交通与空间资料，并保留来源和日期；
- 自行派生的 H3 空间骨架、地名索引、聚合统计和图谱导入文件；
- 贵阳和泰国正式数据包中的规范文件，经凭证、本机路径和运行态脱敏后公开；
- 每个 XLSX 工作表对应的 UTF-8 CSV，以及行列数和 SHA-256 清单。

## 必须排除或脱敏

- API Key、Cookie、浏览器 Profile、登录状态、代理凭证和临时访问令牌；
- 本机绝对路径、缓存数据库、锁文件、采集日志和失败截图；
- 纯重复备份、过期导出、调试 inspect 文件和可从公开内容重建的重复 ZIP；
- 结构化数据中的敏感字段保留列名，但其值统一替换为 `[REDACTED]`。

## 完整性口径

“全量公开”指两个正式源目录中所有具备业务价值的规范文件经脱敏后进入仓库。不将密钥、临时访问参数、操作系统垃圾文件或纯重复备份计为缺失业务数据。每个排除项均在 `data/full-data-manifest.json` 中保留路径和原因。

- 项目自研代码按根目录 `LICENSE` 公开；

## 提交前检查

1. 搜索密钥、令牌、Cookie、Session 和本机绝对路径；
2. 对结构化的敏感列执行字段级脱敏；
3. 检查单文件是否超过 GitHub 100 MiB 限制；
4. 对 JSON 执行语法检查，对 CSV 核对表头、行数和可解析性；
5. 刷新逐文件清单、排除说明和 SHA-256；
6. 推送前审阅 `git diff --cached` 并运行全量验证。
