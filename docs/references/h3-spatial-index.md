## 官方资料中的核心事实

### 为什么使用网格

直接以每一个经纬度点做城市级分析成本很高。网格把事件和 POI 映射到有限的空间单元，使聚合、邻域召回、密度计算和区域比较可以转化为索引查找和集合运算。

### 为什么使用六边形

普通方格的边邻居和角邻居距离不同；六边形的相邻中心距离只有一种，更适合近邻扩散、梯度平滑和近似圆形半径。它并不意味着结果天然精确，因此候选召回之后仍需对原始点位计算球面或投影距离。

### 层级和特殊单元

- H3 从分辨率 0 到 15 共 16 级。
- 分辨率 0 有 122 个基础单元，其中 110 个为六边形、12 个为五边形。
- 每升一级，普通单元面积约变为上一级的七分之一。
- 球面无法只用六边形无缝铺满，因此每一级都有 12 个五边形；遍历算法必须使用可处理五边形的安全 API。
- H3Index 以 64 位值表达单元、边等对象，通常以十六进制字符串存储。

### 官方平均面积参考

| 分辨率 | 平均六边形面积 |
| ---: | ---: |
| R7 | 5.161293360 km² |
| R8 | 0.737327598 km² |
| R9 | 0.105332513 km² |

面积会随单元在二十面体上的位置变化，不能把平均值当作每个单元的精确面积。精确数据应使用 H3 API 对具体单元计算。

## 贵阳项目如何使用 H3

### 两层空间骨架

- R8 是城市主骨架，用于行政区归属、商圈标签、覆盖审计和附近候选召回。
- R7 是粗粒度父层，用于较大半径查询和降低需要枚举的单元数量。
- 骨架必须覆盖贵阳市域内的空格子；`poiCount=0` 不代表市域外。

### POI 查询粒度

- POI 可保存 R9 细索引和 R7 粗索引。
- 查询流程是“定位起点 → 选择分辨率 → 展开安全 k 环 → 等值取候选 → 精确距离过滤”。
- 只查询起点所在单格会漏掉与起点很近但位于邻格的 POI。

### 三类查询不能混为一谈

1. 指名地点：`PlaceAlias` 解析到点锚或格集，再做邻域查询。
2. 用户当前位置：定位直接落格，不需要先经过地名实体。
3. “最热门、评分最高、最适合亲子”：属于业务过滤和排序问题。没有位置限定时不需要 H3；有位置条件时，H3 只负责空间候选集。

### 不能用网格代替的事情

- 最终精确距离；
- 行政区边界附近的逐点归属；
- POI 身份对齐；
- 热度、质量或推荐排序；
- 数据来源和证据可信度。

## 坐标参考系注意事项

H3 API 接收经纬度，但不负责在 WGS84、GCJ-02 和 BD-09 之间转换，H3Index 自身也不携带 CRS 标签。

当前贵阳生产快照为了与高德地图运行时一致，声明并使用 GCJ-02 输入生成内部 H3 索引。这保证了当前系统内部查询一致，但不是可直接与标准 WGS84 H3 数据互换的表示。必须遵守：

- 同一索引集合只能使用一种已声明的坐标口径；
- 用户定位进入查询前必须转换到同一口径；
- WGS84、GCJ-02 生成的 H3 ID 不得混合；
- 跨城市和开放交换层建议使用 WGS84 H3，另存 GCJ-02 展示坐标；
- 若从 GCJ-02 迁移到 WGS84，必须重算所有 POI、GeoCell、PlaceAlias 锚点和派生关系，不能只改字段声明。

## 对文章结论的工程化补充

Uber 文章解释了 H3 的动机和基本性质；本项目另外通过本地测试约束具体实现：

- H3 ID 不具有适合 B+ 树范围扫描的一维局部性，本项目使用哈希等值查找和邻域枚举。
- 父子单元是层级索引关系，不应当作严格的平面几何嵌套证明。
- 行政区统计必须按 POI 点位和边界规则计算，不能简单按整格汇总。
- 大半径查询应切换到粗分辨率，避免高分辨率 k 环枚举成本快速增长。
